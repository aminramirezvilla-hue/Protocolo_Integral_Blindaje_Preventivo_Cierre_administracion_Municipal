# P5-INC-002 — Inconsistencia de estados permitida

**Fecha de detección:** 2026-09-13  
**Rama:** `dev/v0.1.4`  
**Runtime afectado:** `0.1.4-dev.2`  
**Corrección aplicada:** `0.1.4-dev.3`  
**Caso asociado:** `P5-0301`  
**Severidad:** B1 — Crítica / bloqueante para promoción  
**Estado:** Corregida en código; pendiente de re-prueba funcional

## Evidencia de reproducción

Con el perfil **Administrador municipal**, el control **R074 — Obligaciones de transparencia, datos personales y archivos** permitió guardar y persistir la combinación:

- `Estatus diagnóstico = Conforme`
- `Estatus evidencia = Insuficiente`
- `Validación OIC = Pendiente`

La combinación persistía al cerrar y volver a abrir el modal.

## Riesgo funcional

El sistema permitía declarar un control como `Conforme` aun cuando la evidencia mínima fuera insuficiente. Esto producía una contradicción semántica entre diagnóstico y soporte documental, afectaba la confiabilidad del IPER-CATU y podía inducir reportes ejecutivos inconsistentes.

## Corrección aplicada — 0.1.4-dev.3

Se incorpora `js/patch-p5-dev3.js` y se integra en `index.html` y `sw.js` con las siguientes reglas:

1. `Conforme` no puede coexistir con evidencia `No evaluada`, `Sin evidencia`, `Insuficiente` o `Parcial`.
2. La aplicación bloquea el guardado y muestra un mensaje explicativo; no normaliza silenciosamente los datos.
3. `Validación OIC = Pendiente` puede coexistir con `Conforme` cuando la evidencia ya es completa; el cierre definitivo continúa exigiendo `Conforme + Completa verificada + Validado`.
4. La validación se ejecuta inmediatamente antes de la persistencia del modal para los perfiles con edición general.
5. El perfil OIC conserva la posibilidad de validar o rechazar registros heredados, incluso si provienen de estados inconsistentes previos.
6. La identidad de runtime y la caché PWA se elevan a `0.1.4-dev.3` / `catu-er-v0.1.4-dev.3`.

## Re-prueba obligatoria

- P5-0301-A: `Conforme + Insuficiente + Pendiente` → bloqueo, sin persistencia.
- P5-0301-B: `Conforme + Parcial + Pendiente` → bloqueo, sin persistencia.
- P5-0301-C: `Conforme + No evaluada + Pendiente` → bloqueo, sin persistencia.
- P5-0301-D: `Conforme + Completa verificada + Pendiente` → permitido, pero no cerrado.
- P5-0301-E: `Conforme + Completa verificada + Validado` → permitido y cerrado.
- P5-0301-F: cerrar/reabrir modal y recargar Safari → sólo persiste el último estado válido.

La incidencia podrá cambiar a **CERRADA** únicamente cuando todos los casos anteriores resulten `PASS` y no se detecten regresiones en los permisos ya validados en P5-0203.

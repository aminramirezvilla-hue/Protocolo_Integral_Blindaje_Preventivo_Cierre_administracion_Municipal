# P5-INC-002 — Inconsistencia de estados permitida

**Fecha de detección:** 2026-09-13  
**Rama:** `dev/v0.1.4`  
**Runtime afectado:** `0.1.4-dev.2`  
**Corrección aplicada:** `0.1.4-dev.3`  
**Caso asociado:** `P5-0301`  
**Severidad:** B1 — Crítica / bloqueante para promoción  
**Estado:** **CERRADA — re-prueba funcional y persistencia PASS**

## Evidencia de reproducción

Con el perfil **Administrador municipal**, el control **R074 — Obligaciones de transparencia, datos personales y archivos** permitió originalmente guardar y persistir la combinación:

- `Estatus diagnóstico = Conforme`
- `Estatus evidencia = Insuficiente`
- `Validación OIC = Pendiente`

La combinación persistía al cerrar y volver a abrir el modal en `0.1.4-dev.2`.

## Riesgo funcional

El sistema permitía declarar un control como `Conforme` aun cuando la evidencia mínima fuera insuficiente. Esto producía una contradicción semántica entre diagnóstico y soporte documental, afectaba la confiabilidad del IPER-CATU y podía inducir reportes ejecutivos inconsistentes.

## Corrección aplicada — 0.1.4-dev.3

Se incorporó `js/patch-p5-dev3.js` y se integró en `index.html` y `sw.js` con las siguientes reglas:

1. `Conforme` no puede coexistir con evidencia `No evaluada`, `Sin evidencia`, `Insuficiente` o `Parcial`.
2. La aplicación bloquea el guardado y muestra un mensaje explicativo; no normaliza silenciosamente los datos.
3. `Validación OIC = Pendiente` puede coexistir con `Conforme` cuando la evidencia ya es completa; el cierre definitivo continúa exigiendo `Conforme + Completa verificada + Validado`.
4. La validación se ejecuta inmediatamente antes de la persistencia del modal para los perfiles con edición general.
5. El perfil OIC conserva la posibilidad de validar o rechazar registros heredados, incluso si provienen de estados inconsistentes previos.
6. La identidad de runtime y la caché PWA se elevaron a `0.1.4-dev.3` / `catu-er-v0.1.4-dev.3`.

## Resultado de re-prueba

| Caso | Resultado esperado | Resultado final |
|---|---|---|
| P5-0301-A | `Conforme + Insuficiente + Pendiente` bloqueado; no persistir | **PASS** |
| P5-0301-B | `Conforme + Parcial + Pendiente` bloqueado; no persistir | **PASS** |
| P5-0301-C | `Conforme + No evaluada + Pendiente` bloqueado; no persistir | **PASS** |
| P5-0301-D | `Conforme + Completa verificada + Pendiente` permitido; no cerrado | **PASS** |
| P5-0301-E | `Conforme + Completa verificada + Validado` permitido y cerrado | **PASS** |
| P5-0301-F | Tras cerrar/reabrir y recargar Safari persiste sólo el último estado válido | **PASS** |

La comprobación final se realizó **después de recargar Safari**. El panel posterior mostró `5/84` controles evaluados, `4%` de cobertura de evidencia y `2` controles cerrados, sin reaparición de combinaciones inválidas.

## Criterio de cierre

Se cumple el criterio de cierre: `P5-0301-A` a `P5-0301-F` resultaron `PASS`, la persistencia posterior a recarga conserva el último estado válido y no se observaron regresiones sobre la segregación funcional ya ejercitada en P5.2.

**Decisión:** cerrar `P5-INC-002` y habilitar la continuación de P5.3 con `P5-0302 — No subsanable con Ruta A`.
